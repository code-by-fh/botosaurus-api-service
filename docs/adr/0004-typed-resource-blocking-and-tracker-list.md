# ADR 0004: Typed resource blocking and a shipped tracker list

- Status: accepted; decisions 1 and 4 partly superseded by ADR 0005 (see the update below)
- Date: 2026-09-30

> **Update (2026-10-01).** The `trackers` kind and the `true` alias were removed before 2.0.0
> was released. Trackers are no longer blocked; readiness ignores their requests instead
> (ADR 0005), which gives the speed without the detection risk of a client that never loads
> them, and blocking nothing by default needs no alias. `block_resources` now accepts `false`
> or a non-empty, duplicate-free list of `image`, `font`, `media`, `stylesheet`. The shipped
> tracker list, its loader and the refresh script described in decision 4 stay, as the source
> of the domains readiness ignores; its startup check now guarantees that readiness can never
> silently stop ignoring trackers. Everything else below still applies.

## Context

`block_resources: true` told Chrome to skip images, fonts, media and CSS through
`Network.setBlockedURLs(urls=["*.png", "*.css", ...])`. Two problems:

1. **Over-blocking.** The `urls` parameter is deprecated in the CDP version zendriver 0.17.0
   speaks, and Chrome matches its patterns as substrings with implicit wildcards on both ends.
   `*.ico` therefore also blocked scripts and XHR from a host such as `shop.icon.de`, and `*.css`
   any URL containing `.css`. A blocked script can leave the page incomplete, which contradicts
   the central promise of the service.
2. **All or nothing.** Callers who only want speed had to accept the kinds of blocking that are
   easiest to detect (a client loading HTML but no images or CSS stands out to CDN-based bot
   protection) and most likely to hide lazy-loaded content. The least detectable and most
   useful kind, skipping ad and analytics requests, was not available at all.

## Decision

1. **Typed kinds.** `block_resources` accepts `false` or a non-empty list without duplicates of
   `image`, `font`, `media`, `stylesheet` (`BlockedResource`). *(Superseded: the original
   decision also offered a `trackers` kind and `true` as an alias for the four file kinds;
   both were removed before 2.0.0, and `true` is now a `400`.)* Internally the value is a
   `frozenset[BlockedResource]`; empty means no blocking. One plain validator parses the field so that errors appear as a single entry on
   `block_resources` instead of pydantic's per-branch union errors.
2. **URLPattern.** Patterns go to Chrome as
   `set_blocked_ur_ls(url_patterns=[BlockPattern(url_pattern, block)])`, which uses the
   URLPattern constructor string syntax and applies the first matching pattern:
   - File kinds: `*://*:*/*.<ext>?*`, anchored to the end of the path, any host and port, the
     query spelled out so versioned assets match whatever the default for an unspecified
     search component is.
   - Domains: `*://<domain>:*/*` and `*://*.<domain>:*/*`. `/*?*` must not be used: after `*`
     the `?` parses as the optional modifier, not as the start of the query. An unspecified
     search component defaults to the wildcard.
   - The semantics were checked against the spec-compliant `urlpattern` implementation (Rust
     crate, Python binding 0.3.1): `*.ico` no longer matches `shop.icon.de/app.js`,
     `*.css?*` matches `x.css` and `x.css?v=1` but not `x.css.js`, `*.doubleclick.net` does not
     match `evildoubleclick.net`, and an explicit `:*` is needed for non-default ports.
3. **Allow-list first.** `NEVER_BLOCKED_PATTERNS` (Cloudflare challenges and
   `/cdn-cgi/challenge-platform/`, DataDome, HUMAN/PerimeterX, AWS WAF, hCaptcha, reCAPTCHA,
   Arkose Labs, Imperva) is sent first with `block=False` whenever any blocking is active.
   Blocking any part of a challenge, even an image, turns a solvable challenge into a hard
   block.
4. **Shipped tracker list.** Readiness ignores requests to the domains in
   `app/browser/data/tracker_domains.txt` and their subdomains, except the domain the requested
   page is on (its own assets live there). *(Superseded: the original decision blocked them
   through a `trackers` kind; since ADR 0005 they are never blocked.)* The file is generated by
   `scripts/update_tracker_domains.py`, run manually by maintainers:
   - Source: the tracking- and ad-server sections of EasyPrivacy and EasyList, only rules that
     block a whole domain (`||domain^`, options limited to `third-party` and request types).
     Other sections list real sites as embeds (`||soundcloud.com^$ping`).
   - Minus every domain a list exempts as a whole anywhere (`@@||domain^`), because its
     maintainers saw pages break.
   - Minus the anti-bot vendors above and a second never-list: tag managers (Google Tag
     Manager, Tealium, Ensighten), consent managers, experimentation, personalisation and
     geolocation services, fraud detection, and Google's IMA video ad SDK. Sites load content,
     consent state or test variants through them; EasyPrivacy alone carries hundreds of site
     exceptions for Google Tag Manager.
   - Bounded to the 1000 domains best ranked by the Tranco top-1M list (a host inherits the rank
     of its parent domain, except on shared hosting platforms). Every listed domain risks
     ignoring a request that delivers content, so only the domains pages load most are kept.
   - The service never downloads the list. It reads the file once at startup
     (`default_tracker_domains()` in `start_runtime`) and refuses to start with a `ConfigError`
     if it is missing, empty or has a malformed line, so readiness can never silently stop
     ignoring trackers.
5. **No WebSocket blocking.** It is not offered: `Fetch` interception does not see WebSockets,
   `setBlockedURLs` does not reliably block their handshakes, readiness does not wait for them
   so there is no speed gain, what they carry is often the content itself, and a client that
   never opens the socket a page expects is easy to detect.
6. **Verification.** A render with any blocking is never used as an HTTP verification reference
   (unchanged rule, now keyed on a non-empty set).
7. **Observability.** The render timing log carries `blocked=<sorted kinds>` or `blocked=none`.

## Consequences

- Blocking hits only URLs whose path really ends in one of the extensions. Requests that the
  substring patterns blocked by accident now load, which may cost a little speed and fixes
  incomplete pages.
- *(Superseded: the original decision recommended `trackers` as the first choice.)* Ad and
  analytics requests no longer need blocking for speed: readiness ignores them (ADR 0005), so
  the page loads them like a real visitor and returns without waiting for them.
- The tracker list ages. Maintainers refresh it with the script and commit the result; the
  file header records when it was generated. The derived list is distributed under the
  EasyList licence terms (GPLv3 or CC BY-SA 3.0), stated in its header.
- Patterns are case-sensitive, so `IMAGE.PNG` is not blocked. That errs towards loading.
- The URLPattern behaviour was verified with a spec-compliant library, not against the Chrome
  build in the image. A pattern Chrome rejected would fail the CDP call and with it the render,
  which is loud rather than silent; a smoke test against real Chrome after each Chrome or
  zendriver upgrade is still advisable.
